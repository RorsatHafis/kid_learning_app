# Bookeyond Design Engineering
Design is an engineering constraint, not decoration.

Apply hierarchy, rhythm, spacing scale, typography hierarchy, semantic color, contrast, affordance, progressive disclosure, cognitive-load reduction, consistent component states, responsive composition, touch targets, and accessible focus states.

Bookeyond: child UI is playful/premium/warm/safe; parent UI is calm/trustworthy/evidence-led. Avoid generic SaaS cards, neon/casino patterns, visual noise, childish overload, and arbitrary gradients.

Motion must have purpose: orientation, feedback, state change, continuity, delight, or learning reinforcement. Respect reduced-motion preferences. Prefer consistent timing/easing tokens over one-off animations.

When available, use the external Emilowalski design/animation skills for deeper motion craft rather than duplicating them here.
